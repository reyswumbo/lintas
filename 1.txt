🚀 LINTAS ANDROID APP CHALLENGE

One Code. One Transfer. $0 Reward. 📱

We’re challenging developers, beginners, and AI-assisted builders to create Lintas — a simple, lightweight, modern Android app for transferring files between devices using a temporary random code.

The goal is simple:

Send a file → Get a random code → Share it → Receive it on another device.

No accounts.
No complicated setup.
Just a simple way to move files from one device to another.

---

🎯 THE CONCEPT

Lintas is a native Android file-transfer application with two primary sections:

📤 SEND

Upload a file and generate a temporary transfer code.

📥 RECEIVE

Enter the transfer code on another device and download the file.

The experience should feel fast, simple, and intuitive.

---

📤 SEND

Users should be able to select and upload:

- 📹 Videos
- 🖼️ Images
- 📄 Documents
- 📝 Text files
- 📦 Other supported files

After the upload is successfully completed, Lintas automatically generates a random transfer code.

The sender must not choose the code manually.

Example:

"qb8ca-BixA8"

Other examples:

"K7m2Q-xP9aL"
"a82Kd-7XqPz"

The code should be:

- Randomly generated
- Alphanumeric
- Case-sensitive
- Easy to copy
- Easy to share
- Difficult to guess
- Unique enough to identify the transfer

---

🔑 RANDOM TRANSFER CODE

The transfer code is the main identifier for a file.

The code should be generated automatically by the system after a successful upload.

It should not be predictable based on:

- Filename
- Username
- Timestamp
- File type
- Other user-controlled information

Each transfer should receive its own random code.

Once the transfer expires, the code must become invalid.

---

📥 RECEIVE

On another Android device, the user selects Receive.

They enter the transfer code.

For example:

"qb8ca-BixA8"

If the code is valid, Lintas should display useful information such as:

- File name
- File type
- File size
- Transfer status
- Remaining availability time

The user can then download the file.

Invalid, expired, deleted, or nonexistent codes should display an appropriate error state.

---

⏱️ 24-HOUR EXPIRATION

Every transfer is temporary.

Files and their associated codes are available for 24 hours after the transfer is created.

After 24 hours:

- 🗑️ The uploaded file must be deleted
- 🔒 The transfer code becomes invalid
- 🚫 The file can no longer be downloaded
- 🧹 Temporary transfer data should be cleaned up

Expiration must be enforced by the backend/server, not only by the Android application.

---

🔄 TRANSFER FLOW

Device A

Send → Select File → Upload → Generate Code → Share Code

↓

Device B

Receive → Enter Code → Find Transfer → View File → Download

The entire process should be straightforward enough that a new user can understand it without instructions.

📊 TRANSFER INFORMATION

During a transfer, users should be able to clearly understand what is happening.

Consider displaying:

- Upload progress
- Download progress
- File name
- File size
- File type
- Generated transfer code
- Expiration countdown/time
- Transfer status

The generated code should have an obvious Copy action and may also provide a convenient Share action.

📦 APP SIZE & OPTIMIZATION

Lintas should remain lightweight and efficient.

The Android application should be optimized for release builds.

Requirements:

- Enable R8/code shrinking
- Enable resource shrinking
- Remove unnecessary dependencies
- Avoid unnecessary libraries
- Optimize the final release build
- Keep the application footprint as small as reasonably possible

The goal is not simply to make the application functional, but to make it small, fast, and efficient.

---

🔐 SECURITY & RELIABILITY

The application should properly handle situations such as:

- Invalid transfer codes
- Expired transfer codes
- Deleted files
- Interrupted uploads
- Interrupted downloads
- Network failures
- Duplicate requests
- Incomplete uploads
- Corrupted transfers
- Large files
- Server errors
- Unexpected application termination

The backend should prevent expired transfers from remaining accessible.

The random code system should also avoid making transfers trivially discoverable through predictable identifiers.
